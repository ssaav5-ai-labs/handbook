## What broke and how I fixed it
- **Git ownership error:** `git add` failed with "detected dubious ownership in repository" (container user owns a root-mounted workspace). Fixed with `git config --global --add safe.directory /workspaces/handbook`, then everything proceeded.
- **Wrong file modes in first commit:** Files were committed `100755` because the workspace mount made everything look executable. Fixed by `git config core.fileMode false`, `git config core.autocrlf input`, `git ls-files -z | xargs -0 git update-index --chmod=-x`, re-adding executable bit only for `scripts/sync-skills.sh`, and amending the initial commit. Verified via `git ls-files -s`: only `scripts/sync-skills.sh` is `100755`.

## What broke in step 4 and how it was fixed
- **Windows-side commit failed:** the workstation repo had no git identity (the container one was repo-local to the handbook). Fixed repo-locally on Windows with `user.name`/`user.email` plus `core.autocrlf input` and `core.fileMode false` to match the container side and avoid CRLF churn.
- **Empty first gateway reply:** `max_tokens: 10` got eaten by reasoning tokens; retried at 50 and it answered. Note for future calls: leave headroom for reasoning tokens on small `fast` models.
