### Step 3: Gateway key for job search
- LiteLLM v1.106.6 docs checked for two requirements.
- **(a) OpenRouter data_collection: deny:** Must be per-model extra_body. Added two job-only aliases `jobs-fast` and `jobs-reason` (same upstream models as `fast`/`reason`) with `extra_body.provider.data_collection: deny` — matches OpenRouter's provider-routing API shape.
- **(b) Langfuse message logging off:** Per-key logging control is Enterprise. Non-Enterprise approach: job-search server sets `x-litellm-enable-message-redaction: true` header on every request. Redacts prompt/completion text but keeps cost/latency/token metadata in Langfuse. Step 4 unit test must verify the header is sent on every gateway request. Step 3 verify call must include the header.
- Config change: [homelab-gitops#84](https://github.com/ssaav5-ai-labs/homelab-gitops/pull/84) (1 file, 15 lines added)

## Decisions made
- **Per-model no-retention (step 3):** `data_collection: deny` via `extra_body.provider.data_collection: deny` on two job-only aliases (`jobs-fast`, `jobs-reason`), matching OpenRouter's provider-routing shape. Shared `fast`/`reason` unchanged.
- **Per-request message redaction (step 3):** `x-litellm-enable-message-redaction: true` header set by job-search server on every gateway request (non-Enterprise, per-request). Langfuse records cost/latency/tokens only.

### Fixes along the way

- **`activeDeadlineSeconds` location** — the API server rejects `spec.activeDeadlineSeconds`
  on a CronJob; it belongs under `spec.jobTemplate.spec`. [homelab-gitops#109].
- **PodSecurity (restricted)** — the `career` namespace enforces `restricted`, so git-sync
  needed `runAsNonRoot: true` + `runAsUser: 65533`, pod-level `fsGroup`/`supplementalGroups`
  10001, and `safe.directory` via `GIT_CONFIG` env; triage got `runAsGroup: 10001`.
  [homelab-gitops#110].
- **`__main__` guard** — `python -m job_search.triage` exited 0 without calling `main()`
  because `triage.py` had no `if __name__ == "__main__"` guard, so the test job did
  nothing. Added the guard plus per-stage INFO logging and a subprocess regression test;
  `_write_vault` now returns the commit sha. [homelab-agents#32].
- **Proxy ingress** — the first run failed with `IMAP connect failed: Connection refused`
  because the egress proxy's own ingress policy (`allow-ingress-proxy`) admitted only
  `app: job-search`; the triage pod (app: job-triage) couldn't reach the proxy. Widened it
  to `app In [job-search, job-triage]`. [homelab-gitops#112].

## Lessons

- **Check Service names with `kubectl get svc` before writing URLs.** `score_role` failed end-to-end with "unparseable reply after 2 attempts" because `LAB_GATEWAY_URL` pointed at `llm-gateway.llm-gateway.svc.cluster.local`, but the gateway Service is actually named `litellm`, not `llm-gateway`. Resolve the Service name from the cluster (`kubectl get svc -n llm-gateway`) before writing any `.svc` URL. Fixed in homelab-gitops by correcting `LAB_GATEWAY_URL` to `litellm.llm-gateway.svc.cluster.local`.
- **Run slow sync tool calls off the event loop.** `_run_guarded` called the sync scorer directly on the event loop, so a ~36s LLM round-trip starved `/healthz` and tripped the 1s liveness probe, restarting the pod mid-request. Fixed with `asyncio.to_thread` plus a regression test (homelab-agents #26).
- **Hermes reads skills only at startup.** git-sync copies new `SKILL.md` files into the pod within five minutes, but Hermes won't use them until it restarts — after any skill change, `kubectl -n hermes rollout restart deploy/hermes` is required (ask the operator first).
