# 2026-10-23: Prepare Proxmox host and create k3s VM

## Goal
Bring pve01 to a clean, updated, backed-up state and create the single k3s VM from a cloud-init template with OpenTofu, in the homelab-infra repo.

## What I did

### Step 1: Create homelab-infra repo
- Created `ssaav5-ai-labs/homelab-infra` (public) with README, AGENTS.md, and .gitignore.
- Verified Proxmox API reachable at `https://192.168.86.201:8006` → 401 (not yet authenticated).

### Step 2: Free update channel and updates
- Switched to no-subscription repo, disabled enterprise repos.
- Upgraded: `pve-manager/9.2.21`, kernel `7.0.14-23-pve` → `7.0.14-25-pve`.
- Reboot pending for new kernel.
- Reboot done, pve01 back up and reachable.

### Step 3: API access for OpenTofu
- Created `tofu@pve` user, `TofuProvisioner` role with VM-management privileges (bpg/proxmox v0.118.0), API token `tofu@pve!homelab-infra`.
- Token verified: `curl` to `/nodes` returns "pve01" (and "pve02" — second node discovered, not in hardware inventory).
- `.env` is gitignored.
- Created `reference-proxmox.md`.

### Step 4: Backups to USB disk
- Formatted 1 TB Seagate One Touch (sdb) as ext4, mounted at `/mnt/usb-backup` by UUID.
- Added as `usb-backup` directory storage in Proxmox (content: backup).
- No password protection was enabled on the drive.
- Created runbook `runbook-backup-restore.md`.
- Updated `reference-proxmox.md` with storage details.

### Step 5: Debian 13 cloud-init template
- Downloaded `debian-13-genericcloud-amd64.qcow2` from cloud.debian.org, SHA512 verified.
- Created VM 9000 `debian13-cloud` template (virtio-scsi-single, cloud-init, serial console, QEMU guest agent).

### Step 6: k3s VM with OpenTofu
- Created `tofu/` with provider v0.118.0, VM resource for `k3s-01` (ID 101).
- VM: 4 vCPU (host), 5120 MB, 80 GB on local-lvm, vmbr0, IP 192.168.86.211/24.
- `tofu plan` and `tofu apply` succeeded. SSH verified: 4.8 GB RAM, 4 CPUs, 79 GB disk.
- Created ADR-0014: provision Proxmox VMs with OpenTofu (bpg/proxmox) and cloud-init template (renumbered from 0013 after 0013 was taken by the two-node decision).
- Closed "Proxmox provisioning" open question.
- Committed tofu code to homelab-infra repo.

## Two-node run (2026-10-29)

Playbook rewritten for two nodes (ADR-0013: no QDevice). pve02 already joined, both online.

Reprovisioned: provider now reads `PROXMOX_VE_ENDPOINT`/`PROXMOX_VE_API_TOKEN` from `.env`. Removed `proxmox_endpoint`/`proxmox_api_token` from tfvars and variables. Verified no real token secrets in git history.

### Step 2: Updates (already done)

## What broke and how I fixed it
- `parted` not installed on pve01 — used `fdisk` instead.
- Empty UUID in fstab from failed first mount — removed stale line.
- `jq` not installed on pve01 — used `pvesm list` without `--output-format`.
- SHA512 checksum mismatch on cloud image — image updated since Oct 23; imported current version.
- CI failed: no `tofu` binary on runner — added `opentofu/setup-opentofu@v1` step.
