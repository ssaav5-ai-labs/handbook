# 2026-10-29: Playbook 03 run - Installing k3s on two nodes with zram

## Goal
Install a two-node k3s cluster (server on k3s-01 with embedded etcd, agent on k3s-02) with zram swap, and set up kubeconfig.

## What I did

### Step 1: Check the VMs and the repo
- Installed qemu-guest-agent on both VMs (was missing — the template predates the playbook 02 fix). Verified via Proxmox API: both agents respond.
- Added `tofu/outputs.tf` with `vm_ips` output — scripts now read addresses from `tofu output -json vm_ips`.
- Created `k3s/nodes.conf`: k3s-01 server, k3s-02 agent.
- `tofu apply` writes only the new output, no resource changes.
- Full verify: Debian 13, 4 vCPU, ~4.3 GB RAM (4.3 Gi total), 79 GB/59 GB disks, NTP yes, cross-VM reachability yes.

**Pre-k3s memory:**
- k3s-01: 279 Mi used / 4.3Gi, 4.0 Gi available
- k3s-02: 292 Mi used / 4.3Gi, 4.0 Gi available

### Step 2: Compressed swap in RAM (zram) and a safety-net swap file
- zram kernel module present in Debian cloud kernel (6.12.113+deb13-cloud-amd64) — no kernel upgrade needed.
- Installed `systemd-zram-generator` 1.2.1-2 on both nodes.
- Configured: zram = ram/2 (~2.2 GB), zstd, priority 100; `/swapfile` 1 GiB, priority 10.
- Sysctls: vm.swappiness=180, page-cluster=0, watermark_boost_factor=0, watermark_scale_factor=125.
- Rebooted k3s-02 then k3s-01; both came back with correct swap stack. Rerun idempotent.

## What broke and how I fixed it
- `zramctl` and `sysctl` not found by default in non-interactive SSH — Debian 13 puts them in `/usr/sbin/`, which isn't in the default PATH for non-login shells. Use full paths in scripts.
- **install.sh ran locally instead of on the VM.** Rewrote to use SCP + SSH: render configs locally, copy to remote, run installer via SSH.
- **YAML parse error: `cluster-init: true` concatenated to last line of template.** Server template had no trailing newline; `echo` appended to the last line. Fixed by adding trailing newlines and using `printf` for append.
- **Kubelet drop-in `.yaml` extension not recognized.** k3s reads kubelet config from `.conf` files in `/var/lib/rancher/k3s/agent/etc/kubelet.conf.d/`, not `.yaml`. Renamed to `99-kubelet-swap.conf` so it loads after the default `00-k3s-defaults.conf`.

### Step 3: Pin k3s and write configuration
- Version: v1.36.5+k3s1 (stable channel, confirmed on GitHub releases; within one minor of kubectl v1.37.1).
- Bundled components kept: Traefik (v3.7.13), ServiceLB, local-path-provisioner (v0.0.37), metrics-server (v0.9.0).
- Networks: 10.42.0.0/16 pods, 10.43.0.0/16 services.
- Created `k3s/config/server.yaml.tmpl` (token, node-ip, tls-san, secrets-encryption, etcd snapshots at 02:00, kubelet args with resource reservations), `k3s/config/agent.yaml.tmpl` (server, token, kubelet args with lower kube-reserved), `k3s/config/kubelet-swap.yaml` (LimitedSwap), and `k3s/install.sh` (renders config per node role from nodes.conf and tofu output, copies drop-in to /var/lib/rancher/k3s/agent/etc/kubelet.conf.d/, runs pinned installer).
- Token generated into `.env` (64 hex chars). User must copy to password manager from their own terminal.
