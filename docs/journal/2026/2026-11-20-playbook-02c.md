# 2026-11-20: Playbook 02c run

## Goal
Move every repo's dev container off the 8 GB laptop onto a VM on `pve03`, so all of them can run at once and a run survives the laptop sleeping ([ADR-0033](../../decisions/0033-dev-containers-on-a-devbox-vm.md)).

## How it ran
First playbook run where Claude wrote the code as PRs directly (ADR-0038) instead of OpenCode on the laptop; Shawn ran the human steps. Run in parallel with the job-search work on k3s, which touches different repos.

- **Code (2026-11-18):** homelab-infra #11 (`tofu/devbox.tf`, a `devbox` variable with the playbook sizes as defaults, `devbox/prepare.sh`, CI shellchecks it), and a `devbox/devcontainer.json` in handbook #53, homelab-gitops #102 and workstation #7.
- **Before applying:** `free -g` on `pve03` showed 16 GB available next to `k3s-03`; enough for 8 GB more.
- **Step 1:** `tofu plan` first failed with *Missing Proxmox VE API Endpoint*: the token in `homelab-infra/.env` has to be loaded (`set -a; . ./.env; set +a`). Then 1 to add, 0 to change, 0 to destroy; created in 23 s.
- **Step 2:** Docker 29.10.0, containerd 2.4.2, buildx 0.39.0 (pinned, held), tmux 3.5a; root disk grew to 118 GB.
- **Step 3:** the env file was written from the laptop container's own variables (`printf ... | ssh devbox 'umask 077; cat > ~/.devbox/env'`), kubeconfig and SSH key by `scp` from the container, the age key by `scp` from PowerShell (the homelab-infra container doesn't mount it). Nothing printed. All four files `600`, no CRLF.
- **Step 6:** `devpod up` with the SSH provider worked, but `ssh homelab-infra-box.devpod` waited for the DevPod agent and timed out after about 5 minutes, twice. `docker exec` over plain SSH works. The workspace folder is `/workspaces/<repo>-box` (named after the workspace ID).
- **Checks in the container:** gateway URL and key, `GH_TOKEN`, `kubectl get nodes` (three Ready via the VIP), age key, handbook mount, OpenCode 1.19.3: all fine. SSH to `k3s-01` failed with *Host key verification failed* until the shared `known_hosts` got the lab's host keys (`ssh-keyscan`).
- **Step 7:** all four workspaces up; the devbox still had 7.1 GB available. OpenCode kept running in tmux after closing the PowerShell window.
- **Step 8:** `hbx <repo>` finds the container by its `/workspaces/<repo>-box` mount (`docker ps --filter volume=...`), starts the workspace if needed and attaches to tmux; `hb` = `hbx handbook`; the old laptop function became `hbl <repo>`, without the old laptop gateway line.

## Gotchas
- PowerShell mangles double quotes nested inside a command for `ssh`/`docker` (`--format "{{index ...\"...\"}}"` gave a template parsing error). Use single quotes outside, or none inside.
- Commands for PowerShell pasted into the container (and the other way round) were the most common mistake; instructions now name the shell on every block.
- OpenCode's logo shows only "code" inside tmux (the dark-grey "open" renders as black). A true-colour tmux config didn't change it; left as is.

## Decisions
- Keep the devbox a VM, not a k3s pod or an LXC (Shawn asked 2026-11-18): a cluster outage shouldn't take the tools to fix it; Docker in an LXC needs nesting and fights user ID mapping on the bind mounts; and a VM is a firmer wall around the age key and tokens.
- Enter containers with `docker exec`, not DevPod's SSH entries, until DevPod's SSH provider works on Windows.
